## Правила работы с кодом и воркфлоу

### n8n
- Workflow-ы редактирую через `mcp__n8n-mcp__*` инструменты, не через UI пользователя.
- Перед `n8n_update_partial_workflow` всегда `n8n_get_workflow` чтобы посмотреть текущее состояние.
- После изменений — `n8n_validate_workflow` обязательно.
- Никогда не удалять воркфлоу без явного подтверждения пользователя.
- Telegram отправки — через HTTP Request с `$env.<TOKEN>`, не через Telegram-ноду (брендинг).

### Supabase
- JSONB поля (`source_data`, `agent_output` в tasks) передавать **объектами**, не `JSON.stringify(...)`. Иначе строка → constraint падает.
- В Code-нодах читать через `parseMaybeString()` — старые записи могут быть двойно-эскейпированными.

### Документация
- При исправлении бага в воркфлоу — добавлять строку в таблицу "Исправленные баги" в соответствующем `docs/<имя>/README.md`.
- Не создавать новые README/документацию без явной просьбы пользователя.
